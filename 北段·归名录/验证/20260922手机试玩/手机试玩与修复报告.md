## 已落地的改进

| 发现 | 最终处理 |
|---|---|
| 从准备页进入牌桌保留旧滚动，标题与顶栏被卷走 | 切换场景、页面或幕时回到顶部；普通出牌保留当前阅读位置。 |
| 手机牌桌只见进度数，不清楚当前目标 | 在危险卡上方显示当前幕、回合、目标和进度。底栏持续显示心神、进度与香火。 |
| 行动页重复展示整张牌桌，基础动作落在底栏后 | 行动页隐藏牌桌与常驻手牌，基础动作紧接目标；横屏将目标和动作并排。 |
| 援助、取消、构筑等按钮偏小 | 常用触控至少44像素，手牌比较动作46像素；材料判断按钮也补到44像素。 |
| 详情返回后比较列表跳回第一张 | 保存并恢复弹窗阅读位置；紧凑详情保留卡图，完整作用放在旁边。 |
| 横屏误切桌面布局，找牌需要反复长滚动 | 低高度横屏使用手机布局和固定操作栏；短屏收起迷你手牌，底栏“手牌”随时打开比较。 |
| 温的援助作用和次数在使用前不清楚 | 按钮显示“援助·回5护3”，旁边明确每场一次；不另加确认弹窗。 |
| 挡住反光后仍显示未防住的原惩罚 | 根据当前防护、预留应对与已结算状态更新预告，显示“已应对”或“已预留”。 |
| 正确判断后承诺前进，却被结算干扰扣回进度 | 明确仍需结算干扰、保持目标达成才能前进；提示失足等直接扣心神，护身只抵挡对手施压。 |
| 行动页缺少清楚的扣费、扣血摘要 | 显示本次资源、目标与日志变化；行动页也能看到“刚才发生了什么”。 |
| 手机行动页选多个压制目标时可能看不到桌面 | 所有需要选目标的操作统一切回牌桌，并临时收起遮挡目标的手牌。 |

## 苹果安全区域

入口加入 `viewport-fit=cover`；统一使用 `safe-area-inset-top/right/bottom/left`。背景可以延伸到屏幕边缘，主要内容、弹窗与底部操作避开浏览器报告的安全区域。横屏两侧安全区域与底部手势区域分别处理，不只补一个固定底部空白。

弹窗使用可视窗口高度，监听 `visualViewport` 的尺寸与偏移；正文可滚动，长剧情不被固定高度裁掉。输入框保持16像素字号；没有禁用页面缩放。实现依据：[WebKit安全区说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)、[动态视口单位说明](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)。

工程矩阵：Chromium与桌面WebKit各跑以下6组，共12组全部通过：320×568、375×667、390×844、393×852、430×932、852×393。纵向注入47/59像素顶部、34像素底部；横向注入59像素左右、21像素底部，检查正文与按钮的边界和可操作性。**这些数值是非零安全区压力测试，不能当作真实机型测量或苹果刘海模拟器。**

另把可视高度缩小到输入状态检查弹窗，验证搜索、关闭与位置恢复；没有调起真正的iOS键盘，也没有模拟Safari地址栏真实动画。
