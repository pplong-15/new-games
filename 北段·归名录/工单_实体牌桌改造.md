1. `.card.physical-card.card-v2::before` 里的

2. `.risk-card::after` 里的

改完立即用第 5 节的方法截图确认。如果透明框的比例不对（卡框图是 400×600，卡片是 168×232），调 `background-size` 和 `clip-path`——可参照旧原型 `tabletop.css` 里 `.physical-frame` 的写法：


```css
@media(max-width:760px){
 .hand-section.physical-hand{position:fixed;left:0;right:0;bottom:0;z-index:40;
   height:168px;min-height:0;max-height:168px;margin:0;padding:6px 8px 8px;

 .tabletop.battle{padding-bottom:214px}
}
```

**注意两个当初踩过的坑**（旧原型里都修过）：
1. 有一条 `.hand-section{min-height:300px}` 会覆盖你设的 `height`，必须同时写 `min-height:0`，否则手牌区仍是 300px 高，会盖住上方元素并吃掉点击
2. 手牌容器若向上溢出，会拦截上方按钮的点击（`.hand.fan-hand` 要限高 + `overflow-y:hidden`）

修完必须用 `devices['iPhone 13']` 实测：手牌区 `bottom <= 视口高`，且「打出」按钮能真实点中。

### ② 桌面手牌只露出 44–48%

# 第四轮：把牌做成恐怖的核心（三个层次全做）

用户判断：**"卡不够恐怖，这才是核心。卡恐怖了、加入民俗恐怖元素、再配合打出时的突脸动画，才能达到效果。我们应该把牌作为改动的核心。"**

用户要求三个层次全做，**并且反复强调：改完一定要契合原玩法和剧情。**

## A. 上一轮已完成的（不要重做）

1. **点卡弹窗已消除** — 手牌 `data-action` 从 `inspect` 改为 `play`，点卡面直接出牌（实测手牌 6→5、无弹窗）。看详情改为**悬停原地放大 1.34 倍**，放大后 `.card-v2-target` / `.card-v2-condition` 自动展开。牌库内的卡仍为 `inspect`
2. **突脸动画** — `playCard()` 里克隆卡面插画到屏幕中央（`.bd-lunge`），四周压黑（`.bd-blackout`），中途变脸，屏幕抽动（`body.bd-jolt`），全程 0.62s，已做 `prefers-reduced-motion` 降级

## B. 主题锚点（所有恐怖化的唯一来源，不得偏离）

六案标题全部围绕**灯**与**名**：

```
第一案《犬灯照夜》  第二案《沉灯照客》  第三案《白衣借名》
第四案《双烛遗书》  第五案《归棺旧影》  第六案《黄灯无客》
```

游戏名《归名录》，主角沈砚是**修书人**，核心动作是**核对材料、说破来由**，开场引言是父亲留下的一句「**不要只看誊清的那份**」。

**所以这部作品的恐怖内核是：**

| 母题 | 含义 |
|---|---|
| **灯** | 照见与照不见。灯照到的地方是安全的，照不到的地方有东西；灯灭、灯换手、无客之灯 |
| **名** | 名字即身份。被叫名、借名、替名、销名、归名。**叫得出你名字的东西，比会咬人的东西可怕** |
| **录** | 记录会被誊改。誊清的那份是干净的，底稿上有别的东西 |

**红线：不要往里加通用鬼怪。**不要僵尸、厉鬼、血手印、吊死鬼。这部作品的恐怖必须来自「名字被人动过」「灯照不到那半边」「誊清本和底稿对不上」这类**记录与身份的错位**。

## C. 层次一：卡牌文本（624 张，零美术成本，先做）

### 现状问题

现在的卡是一套**侦探工具箱**，与民俗恐怖零关系：

```
强光手电 / 清点随身 / 灯下细核 / 横刃拦门 / 随身药箱 / 并置异本
```

### 改写原则

**不是把"手电"改成"鬼火"，而是让日常物件带上不祥。**效果与数值一字不改，只改名字与描述的说法。

三条具体手法：

1. **把工具的作用说成"它在替你做什么"**
   `强光手电 · 挡住反光` → **照不见的那半边** · 照过去的地方，暂时不会有东西
2. **给代价留一句暗示**
   `清点随身 · 抽2弃1` → **数一数少了什么** · 抽两张；你得丢掉一样，它才肯罢休
3. **让防护牌记住是谁替的**
   `横刃拦门 · 护身+5` → **横刀在门口** · 替你挡一次。**它记得是谁替的**

### 执行要求

- 覆盖全部 624 张（可复用现成的 `card-names.js` 覆盖层机制，新增 `card-copy-horror.js`）
- **只改 `name` 与描述文本，绝不改 `id` / `cost` / 数值 / `effect` / `mode`**
- 人物卡（`mode==='person'`，24 张）**不改名**——它们是真实人物（温既白、何巡、顾承安等），改名会破坏剧情
- 按案分配意象：第一案偏「灯照夜」、第三案偏「借名」、第五案偏「归棺」，避免六案用同一套词
- **先做 20–30 张常用牌给用户定调子，认可后再扩到全量**

# 第四轮补充：组合技、突脸的触发规则、主流对标

用户追加要求：**「卡牌和突脸得是结合的」「应该设计一些特定卡牌的组合技」「去查一查主流卡牌游戏的玩法，我们对标过来」**。以下是调研结论与落地方案。

## J. 一个已经存在但没建完的系统（先读这节，它改变优先级）

V2 自带「连招筹码」系统：**专注 / 信任 / 脚步**，各上限 5，显示在牌桌中部。

统计全卡池后发现严重失衡：

```
产出筹码的卡（enabler）： 215 张
消耗筹码的卡（payoff）：  11 张
                        ≈ 19.5 : 1
```

**结论：地基已经打好，上层建筑几乎没建。**玩家攒了一堆筹码却几乎没有牌能兑现，所以筹码沦为装饰数字（界面上长期显示 0/5），这也正是资深玩家那句批评的根源——「池子里没有任何一张牌引用另一张牌，没有引擎也没有 combo」。

**所以组合技不需要发明新系统，只需要把 payoff 补上。**这是本轮性价比最高的改动。

现有 payoff 的写法（照此扩写即可）：

```
视线复走 — 通路+1；若有脚步，调查+1
交班追核 — 交涉+1；若有脚步，抽1牌
前踝绊倒 — 压制目标1；目标压力−1；若有脚步，打断目标本轮攻击
限定案发区间 — 调查+2；专注+1；若专注至少2，抽1牌
```

## K. 主流对标（调研结论）

来自 Slay the Spire 一系 deckbuilder 的成熟模型，建议直接套用：

1. **Enabler / Payoff 配对**：协同的本质是「使能者 → 收益者」。收益要显著到值得为它构筑，但不能强到碾压
2. **Bridge card（桥牌）**：关键一条——**payoff 卡在没有筹码时也不能是废牌**。写法是「基础效果 + 若有 X 则追加」，而不是「必须有 X 才能用」。现有的「视线复走」就是正确范式
3. **分档兑现**：同一张牌按筹码多寡给不同回报（若有 1 / 若至少 3 / 若满 5），让攒筹码有持续动力
4. **小牌组、清晰计划**：V2 是每场 30 张固定构筑，已符合
5. **平衡红线**：设计 deckbuilder 最难的不是写卡，是调数值到**没有任何单一 combo 能让游戏变得无聊**

### 建议补的 payoff 档位（保守起步）

| 筹码 | 主题对应 | 建议 payoff 方向 |
|---|---|---|
| **专注** | 看得清 | 调查类收益、材料判断相关（呼应「灯照见」） |
| **信任** | 人肯说 | 交涉类收益、人物协作（呼应「名」） |
| **脚步** | 走得动 | 通路/脱险收益、压制打断（呼应「路」） |

数量建议：每种筹码补 **8–12 张** payoff，先做一案的量给用户看，认可后再扩。

## L. 突脸必须和卡牌绑定（这一条推翻当前实现）

**调研结论：滥用 jump scare 会导致脱敏。**玩家一旦预期到惊吓就不再害怕，有效的惊吓需要铺垫（cue + buildup），并遵循**张弛循环**：慢慢积压 → 给一次惊吓 → 短暂放松。

**当前实现是「每次出牌都突脸」，必然脱敏，必须改。**

建议的触发规则（这一套正好把三个需求焊在一起）：

| 时机 | 演出 | 理由 |
|---|---|---|
| 普通出牌 | **不突脸**，只保留墨痕 + 卡片吸入 | 保持节奏，留出「弛」 |
| **组合技兑现**（筹码达标的 payoff 生效） | **突脸** | 攒筹码=铺垫，兑现=释放。玩家会主动追求它 |
| 危险的规矩发作（索取/应名等） | 牌桌沉一下（已实现） | 压迫来自环境 |
| 说破来由（材料判断答对） | **正向演出**：灯亮、暗角退去 | 与恐怖相反的释放，对比才有起伏 |
| 判断答错 | 短促的暗色闪动 | 代价要有体感 |
| 每幕首次遭遇危险 | 一次轻度突脸 | 建立本幕基调 |

**核心：突脸从「每次出牌」变成「你自己攒出来的高光时刻」。**这同时解决了脱敏、让组合技有仪式感、让恐怖成为奖励而非骚扰。

实现提示：现有突脸代码在 `app.js` 的 `playCard()` 内（`.bd-lunge` / `.bd-blackout` / `body.bd-jolt`），改成按「本次出牌是否触发 combo」决定是否调用即可，引擎需要在出牌结果里回传一个标记（例如 `result.combo=true`）。

## M. 与美术的结合（层次三的重点）

为**触发突脸的那批 payoff 卡**单独准备「变脸版」插画——同一场景但有东西回头 / 多出一只手 / 灯灭了 / 誊本上多了一行字。在 `.bd-lunge` 的 46% 关键帧切换过去。

这样美术投入集中在 **20–30 张会突脸的关键卡**上，而不是 85 张全做，性价比最高。

## N. 本节的额外验收标准

1. payoff 卡在**没有筹码时仍然可用**（bridge card 原则），不得出现「攒不到筹码就是废牌」的设计
2. 补完 payoff 后，筹码的实际消耗率要能在实战中体现（脚本统计：一场里筹码达到 3 以上的回合数、payoff 触发次数）
3. 突脸触发频率：**一场 18 幕中不超过 8–10 次**，且不得连续两回合触发
4. 四套推荐构筑仍能通关 108 场，且没有任何单一 combo 能让通关回合数骤降到异常值（对照现有基线：482 / 474 / 434 / 463 回合）
5. 组合技的文本必须能让玩家看懂「我要攒什么、攒到了能干什么」——上一轮的教训是机制藏起来等于不存在

## Q.5 突脸「变脸版」插画（本轮新增，最关键）

每张会触发突脸的 payoff 卡，需要**一对**插画：常态版 + 变脸版。两张构图、光源、机位必须**完全一致**，只改一处。

```text
画面指令：与 <常态版文件名> 完全相同的构图、机位、光线与物件位置，
只做一处改变：<变化点>。
其余一切保持不变，以便两张图叠化时只有该处发生变化。
```

变化点的写法（每张挑一个，不要叠加多个）：

- 原本背对的人，现在**脸转过来了一点点**，只到能看见一只眼
- 名册上原本空白的那一行，现在**写上了字**
- 灯原本亮着，现在**只剩一缕烟**
- 地上原本只有一道影子，现在**有两道**
- 门原本关着，现在**开了一条缝，缝里是纯黑**
- 桌上原本三只碗，现在**四只**

**守住**：变脸版不要换成鬼脸特写、不要加血、不要糊黑雾。它的恐怖来自「刚才不是这样的」。

# 第六轮：中式恐怖的文化内核（神鬼观 / 道家 / 萨满 / 民俗仪式）

用户要求：**「要融入中式恐怖的元素，比如神鬼观、道家文化、萨满文化、民俗仪式等。」**

## T. 为什么这些元素天然契合本作（不是硬塞）

中式恐怖的精髓**不是随机吓人，是「有一套你必须遵守的规矩」**——犯了忌讳才出事，守住规矩就能活。这与本项目已实现的「危险守规矩」机制（索取/应名/背后有人）是同一个骨架。

更要紧的是：**这几类文化的核心母题，全都落在「名」上**——而本作就叫《归名录》。

| 文化元素 | 与「名」的关系 | 本作的现成接口 |
|---|---|---|
| **生死簿 / 阴司名册** | 名字在册即在世，销名即身死 | **就是"归名录"本身** |
| **叫魂（喊名字招回失魂）** | 被叫到名字不可轻易应答 | **已实现的「应名」trait** |
| **替身 / 替死鬼** | 用另一个名字顶替自己 | 随行者替你承伤 |
| **牌位 / 神主** | 名字的实体载体 | 卡牌本身 |
| **烧纸书名** | 写名焚化＝把东西送走 | 弃牌 / 送别 |
| **符箓护名** | 以符护住名字不被取走 | 护身 |
| **招魂幡（白布书名）** | 第三案《白衣借名》 | 已在剧情里 |

**结论：不需要新发明设定，只需要把已有机制的"说法"换成这套文化语汇。**

## U. 四类文化元素 → 具体可落地的内容

### U.1 神鬼观：名在册则在世

核心观念：**人的存在依赖于"被记录"**。册上无名者不得入门、不得受祭、不得还乡。

- **卡牌方向**：销号（抹名）、补录（添名）、认名（确认身份）、无名（失去记录的状态）
- **机制方向**：被「销号」的随行者攻击力下降或不能被治疗——**呼应概念稿里「移除一个敌方随从的名字，使其攻击力 −2」**
- **敌人方向**：「册上没有的东西」——它存在，但任何记录里都查不到它

### U.2 道家：文书与法度

核心观念：**阴阳两界都按文书办事**。道教科仪里有上表、章奏、度牒——**鬼神也要走流程**。

- **卡牌方向**：符（写名的纸）、敕、印、度牒、章表、镇物
- **机制方向**：**「合乎法度」的行动有效，不合的无效**。例如某些危险只能用特定"文书类"牌应对，硬打无用
- **气质把握**：道家的恐怖是**秩序感的恐怖**——不是混乱，是"它按规矩来取你"

### U.3 萨满：请神、附体、出马

核心观念（北方民间）：**神/仙借人身说话**，跳神者在仪式中不是自己。

- **卡牌方向**：请神、顶香、上身、退神、封口
- **机制方向**：**代价型增益**——借来的力量很强，但本回合你失去某种控制权（例如不能自选目标、手牌被随机弃置）。这与已有的「欠名」系统完美接续
- ⚠️ **边界**：出马仙（狐黄白柳灰）等具体民间信仰，**用"借力要还"的抽象机制表现即可，不点名具体仙家**，避免冒犯真实信仰群体

### U.4 民俗仪式：日常里的忌讳

核心观念：**恐怖藏在"不能做的小事"里**——夜里不能叫名、不能应答、不能回头、镜不照床、筷不插饭。

- **卡牌方向**：叫魂、喊名、回头、掩镜、收灯、送客
- **机制方向**：**忌讳系统**——某些行动在特定条件下会触发惩罚。例如：连续两回合做同一件事、在某类危险在场时使用某类牌
- **这是最容易做出彩的一类**，因为玩家能立刻理解"我犯忌讳了"

第六轮写的「不点名具体仙家」「不使用真实术语」过于保守，**现予推翻**。理由：这些术语属于公共文化遗产，中国文学传统（《西游记》《聊斋志异》《子不语》）历来大量使用，用在虚构作品中既正当又能带来真实厚度。自造词反而会让作品显得轻浮。

|---|---|
| 用真实术语作卡名（符箓、禹步、掐诀、敕令…） | ✅ **应该这么做** |
| 卡牌效果对应该术语的真实功能 | ✅ **应该这么做** |

# 第八轮：卡牌与剧情的匹配度诊断（发现内容缺口，改变优先级）

用户问：**「整个牌的技能逻辑都匹配了剧情了么？」**

答：**没有。而且查出的问题不是"名字不搭"，是后两案的卡根本没做完。**

## AE. 三层诊断（均为实测数据）

### AE.1 案件覆盖断崖 —— 最严重，属于内容缺口而非设计偏差

按 `sourceCase` 字段统计 624 张卡：

```

第1案     153 张
第2案     120 张
第3案     112 张
第4案      81 张
第5案      10 张   ← 断崖
第6案       1 张   ← 几乎空白
```

**第 6 案《黄灯无客》的全部专属卡只有 1 张**——人物卡「阿豆」，效果「入场：抽1牌。每轮首次应对成功后：下轮费用+1；脚步+1」，与「满堂灯火却一个客人都没有」这一主题无任何关系。

**后果**：玩家打到第 5、6 案（共 36 场，占全作三分之一）时，手里用的仍是第一案那套牌。终局体验最差，而终局恰恰是作品的高潮。

**这一条的性质是「内容没做完」，不是「做偏了」。应排在所有重构之前。**

## AK. 修复：一个由「失败惩罚」引发的耦合 Bug（重要教训）

**现象**：玩家反复卡在第一场第一幕，材料判断反复提交、反复被拒，提示只说「先达到本幕准备与现场要求」。用户报告为「第二轮都没过去」。

**根因**（此 Bug 由上一轮我方改动引入，非接手方责任）：

```
本幕判断的前置条件：  仍在施压 1 · 需降至 ≤ 1
上一轮加的失败惩罚：  答错 → 危险压力 +1（1 → 2）
叠加结果：            压力 2 > 1 → 判断被系统锁死
```

玩家答错一次后，判断入口就被自己的惩罚关掉了，而提示文案没有指向「先去压制危险」这条出路。实测：第 1 次答错压力涨到 2，第 2–10 次提交全部被拒。

**已修**：答错的代价改为**心神 −2**，不再触碰压力。验证：

```
错1: 压力=1 心神=28
错2: 压力=1 心神=26
错3: 压力=1 心神=24
答对: ✓ 通过 → 危险压力归 0、标记「已说破」
```

代价仍然存在（三次答错掉 6 点心神），但不再关掉玩家的出路。备份见 `engine.js.bak3`。

### 教训（请接手方在后续所有改动中遵守）

> **任何给「失败」加的代价，都必须先确认它不会触碰别的系统的准入门槛。**

本作中已知的门槛型条件至少有：
- 材料判断的 `仍在施压 N · 需降至 ≤ N`
- 目标行动的 `数值准备已经足够` 拦截
- 随行位上限 3
- 救援幕的 `binds === 0 && captives.length === 0`

给任何一项加惩罚（涨压力、加束缚、占位）之前，**先查它是不是某个门槛的判据**。这类耦合 Bug 不会在单元测试里暴露，只有连续多回合的实际游玩才会撞上。

### 附带教训：自动化试玩脚本的陷阱

本轮我方两次误判「游戏卡死」，实际都是脚本问题：

1. 第一次：脚本只点手牌，没点基础行动 → 调查永远 0/2
2. 第二次：脚本用固定关键词（"调查"/"压制"）匹配按钮，但**目标行动按钮的名字每一幕都跟着剧情变**（第 1 幕「核对失物次序」、第 2 幕「查看客栈后门」）→ 匹配不到，通路永远 0/2

**正确做法**：目标行动按钮固定是 `.table-actions` 里的**第 2 个**，用位置索引而不是文字匹配。若 cursor 中的试玩 agent 也报告「卡住」，请先确认它是否踩了同一个坑。

# 第九轮更正：两条此前写错的结论

## AM. 更正一：目标行动按钮**不是**固定的第 2 个

第九轮 AK 节末尾我写过「目标行动按钮固定是 `.table-actions` 里的第 2 个，用位置索引而不是文字匹配」——**这是错的，请勿照做。**

实测（第一场第一幕，逐回合打印）：

```
R1  .table-actions[1] = 「核对失物次序 · 调查 +1 · 1香火」   ← 是目标行动
R2  .table-actions[1] = 「撑身护住 · 护身 +3 · 1香火」       ← 变了！
R3  .table-actions[1] = 「撑身护住 · 护身 +3 · 1香火」
```

按钮列表会随本幕状态变化（目标达成后目标行动会消失或禁用，顺序随之改变）。

**正确做法**：按当前目标的文字动态匹配。目标行动按钮的文案总是包含本幕目标的进度名（调查 / 通路 / 交涉 / 护身…），可从 `.objective-plaque strong` 读出当前目标名再去匹配，或匹配按钮文案里的 `· <目标名> +1 ·` 模式。

## AN. 更正二：第一回合进度「归零」是设计，不是 Bug

实测第一幕的准备进度变化：

```
R1: 行动前 0 → 行动后 1 → 回合末 0   ← 被清掉
R2: 行动前 0 → 行动后 1 → 回合末 1   ← 正常
R3: 行动前 1 → 行动后 2 → 回合末 2   ← 正常
```

只有第一回合末会清。原因写在目标面板的「回合末会发生」区块里：

> **反光打断：本幕首次结算时调查 −1。可用基础「先护现场」应对。**

这是一次性的开幕干扰，**有明确对策**（基础行动「先护现场 · 挡本幕干扰」），设计本身是好的——它教玩家开局先护场。

**但存在体验问题**：玩家（和自动化脚本）容易漏看这行提示，第一回合白干一次还以为游戏坏了。用户报告的「第二轮都没过去」有一部分来自这里。

**建议**：进度被干扰清掉的那一刻，在反馈区给一条明确的即时提示，例如
「反光打断：本幕首次结算，调查 −1。下次可先用『先护现场』挡掉。」
现在这条信息只在回合开始前的预告区，事后没有任何反馈说明进度为什么没了。
