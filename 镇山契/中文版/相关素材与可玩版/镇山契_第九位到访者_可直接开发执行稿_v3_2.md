## 0. 给开发者的直接指令

请把本项目实现为一款**完全离线、纯静态、可双击打开的中文网页档案悬疑游戏**。玩家扮演历史专卷数字化复核项目的卷宗质检员，在一个工作台和五个年代、机构、语言完全不同的虚构网站之间检索、比较、叠图、校准、排列和提交材料。

开发时必须遵守以下十条：

1. 不把本作做成“点下一步读剧情”。每次关键结论都必须来自玩家的比较、排序、筛选、叠图或结构化举证。
2. 不在按钮、标题、颜色或 CSS 类名里泄露答案。不得出现“正确线索”“真凶”“破解密室”“儿童祭祀核销”等作者视角命名。
3. 公开历史页面可以被玩家乱序访问，完整深链始终返回同一正文；故事进度不能控制公开资料是否存在。
4. 只有工作台派生产物和制度上确属限制阅览的附件可以设置门禁；门禁必须同时存在于页面渲染和提交处理器。
5. 五个外站必须有足量普通内容、相邻内容和可下探的假路线，不能像同一套解谜卡片换皮。
6. 三项死亡的具体行为人、23:44 的 M1 身份、超自然因果必须保持未决；不能因为玩家查到林文就自动宣布“凶手已找到”。
7. `creatorTruth`、作者私有死亡序列、专业评审原始附件不得进入公开构建包。
8. 玩家自由备注只做长度、重复和转义校验，不用正则表达式审判语义；事实判断只靠结构化命题与来源组合。
9. `prototype` 构建可以完整试玩，但凡专业 QA 仍为 `pending` 的命题，只能显示“待复核/候选重构”并禁用确认；`release` 构建必须直接失败。
10. 最终不是“破案成功”，而是生成三份复核建议和一张世界内回执；回执明确写“原始卷宗未被修改”。

### 0.1 成品形态

```text
dist/
├── index.html
└── assets/
    ├── app.js
    ├── app.css
    ├── images/
    ├── scans/
    ├── audio/
    └── icons/
```

- `index.html` 使用 `<script defer src="./assets/app.js"></script>`；
- 不使用 `type="module"`，不拆包，不运行时 `fetch()` 本地 JSON；
- 不依赖后端、数据库、CDN、真实 API、远程字体、统计、登录或 Service Worker；
- `file://` 双击和 HTTP 静态服务两种模式都能完成全流程；
- 所有虚构域名只显示在游戏浏览器地址栏，实际链接全部是本地 Hash 路由。

### 0.2 原型与发行

| 构建模式 | 用途 | `pending` 命题 | 终局 |
|---|---|---|---|
| `prototype` | 开发、内部试玩、内容校准 | 显示世界内“材料待复核”，不得伪装确认 | 可走到提交预览，但回执标“演示构建” |

这不是要求开发暂停。**开发者现在就应完成全部页面、数据、交互、错误路径、存档和自动化测试；只是不能在 QA 未通过时输出正式发行包。**

## 1. 不可变世界正典

### 1.1 玩家身份与开场理由

玩家是“槐县公安局—县档案馆历史专卷数字化复核项目”的卷宗质检员。2026 年水损卷抢救时发现，1998 年黑祠堂案与北坡滑坡卷都曾在箱脊手写简称 `HS-98`，导致一袋桥头底片在 2004 年被扫入错误目录。同年北坡加固工程移交了受限材料，系统仅提示“可能存在关联”，不提前说明儿童埋藏线。

初始工单：

> **QA-26-0813-447**  
> 请确认底片袋 B 应归入 `HS-98-0717` 还是 `GR-98-0719`，并核对卷内人员数字不一致问题。

开场只给四项材料：

- 破门记录：正殿内发现 5 人；
- 当晚登记：共有 8 名活人先后进入正殿；
- 错卷底片：23:44 拍到一名无法凭底片直接识别的男子向村外走；
- 急救页 OCR 残句：“……八个……又……一个……”。

玩家不是受命破案，也无权定罪。玩家只能：核对目录、建立跨卷参见、生成公开索引纠错建议、生成限制阅览附卷建议、生成刑事复核线索函并等待主管审核。

### 1.4 空间与门闩合同

- 正殿唯一成人室外路线是南侧双扇槐木门；
- 窗有完整铁栅，所有通风、送食、排水开口均不能供成人通行；
- 北墙后隐藏室净长 6.8 米、宽 1.18 米、高 2.05 米；
- 隐藏室唯一成人通道是通向正殿的 62×168 厘米木板门；
- 两道铁插销位于正殿侧，插销闭合时里面的人不能自行打开；
- 22:43 由正殿侧开启，开启者身份保持未决。

门闩候选结构：内开双门；146 厘米、5.9 千克木杠左端转轴；东侧漏斗承槽和止退背板；8 毫米锥形暂托销；2.6 毫米红棉绳以无结 U 形回收套挂入销颈；门外抽销后木杠靠重力落槽，再放一端抽回整绳。

**机关的四个命题必须分开：**

1. 结构在几何上可行；
2. 案发现场痕迹符合该结构；
3. 门外操作者是谁；
4. 三名死者由谁造成。

前一项不能自动证明后一项。正式确认门闩还必须有铁销、双股纤维、轴向划痕、新鲜重击、录音落槽声、U1 接触痕迹、门外受力足印，以及 1:1 湿态和 0—3 毫米错位条件下连续 20 次成功的原始记录。

### 1.8 契文与滑坡

- 1968 原抄存在“三童执灯、一人守夜”等文本；
- 1970 秘密改本出现“三童镇基、一人守山”；
- 1982 县报已经公开刊印“守人离，三日北坡开”；
- 1998-07-19 23:41 的滑坡有充分的强降雨、页岩失稳、地声和首报支持；
- 文本早于案件和约 72 小时吻合均可确认；
- 自然机制充分不等于超自然被否定，时间吻合也不等于超自然已证实。

终局固定表述：

> 自然机制足以成立；契文成文时间与灾害日期的吻合也已成立；两者之间是否存在除此之外的因果，现有档案无法检验。

## 2. 玩家体验与反转结构

### 2.2 四层合理误信

| 层次 | 玩家当时可合理相信 | 玩家主动动作 | 被收窄的判断 | 新问题 |
|---|---|---|---|---|
| 1 | 阿山在密室内杀死三人，旧帖说“惊吓自掐”也许是真的 | 比较论坛快照、尸检、锁链半径、血迹区 | 死因不同；阿山不能解释门外落杠，也不支持其为唯一实施者 | 门怎么从外面形成内杠？ |

### 2.4 一次只发布一条工作更新

工作台更新不是“系统替玩家总结真相”，只使用制度语言，例如“关联附卷阅览申请已受理”“有一项比较结果可加入待审包”。

规则：

- 只在玩家返回 `#/workbench/inbox` 或点击“刷新工单状态”时调用 `advanceOneUpdate()`；
- 每次最多发布一条；
- 渲染页面不推进状态；
- 新更新先获得焦点，之后才显示下一动作；
- 浏览器 Back、刷新和重开都保留未读更新；
- 玩家真正阅读后才记录 `ACKNOWLEDGE_UPDATE`；
- 重置清除未读与临时焦点；
- 提前找到后期资料仍需分次返回，不得合并反转。

- 页面变化同步更新 `<title>`、一级标题和焦点；

1. **外部去向核查**：逐人查迁出、医院、村医、墓地、河道；生成《外部去向核查回单》。先呈现生活材料，不立即展示遗骸。

3. **行为矩阵**：将头部击打、颈部压迫、心脏事件、离场、门外落杠分开；候选包含三老、林青、U1、阿山、外部人员和双人协作。玩家必须形成至少两套与痕迹相容的行为图，生成 `R11-BEHAVIOR-ALTERNATIVES`。

系统最终只显示：

> 现有材料无法把三项死亡行为唯一分配给同一人或某一组人。

## 7. 三条多步错误路径

错误路径必须和主线同权，不标红、不变灰、不显示“支路”。每条都需要2—4步才能证明正常，且闭合原因是时间、空间、材质或保管链，而不是作者说“这不是线索”。

### 7.1 赵成海与红绳

```text
两盘红绳领物单
→ 次日盘点少一盘
→ 卫生室22:19—00:05连续处置 + 近路22:16中断
→ 防汛绳为新制涤棉混纺，门闩残留为旧棉纱左捻
→ 缺盘在沙袋捆扎清单核销
```

只排除赵成海操作门闩，不证明 U1 杀人。

### 7.2 2004 日记伪造

```text
PDF创建于2004
→ 同批427册均为1990年代纸本
→ 1998封存清单、封袋号、页数、缺角位置对应
→ 2004逐页数字化批次与校验范围一致
```

只确认“纸本在1998已封存、扫描件入库后未改”；纸本文字仍需其他证据支持。

### 7.3 废矿暗道

```text
民俗游记说庙后有矿
→ 1992闭坑图确有入口
→ 坐标、高程、剖面叠加
→ 终点距正殿184米、低26米，中间连续页岩
→ 封堵验收和1998剖面无贯通
```

排除矿道，不提前排除北墙建筑夹层。

### 7.4 两条可错过的普通误认

这两条不产生阶段结果，不计入通关条件，只增加“玩家自己走进去再走出来”的自由度。

**同名林文**

```text
报刊搜索“林文”
→ 1996县农机厂技术比武二等奖“林文”
→ 同名者职工登记：1964年生、住城西、1998仍在岗
→ 获奖照片与厂志连续记录
```

闭合：这是另一名同名成年人，只训练玩家用出生年、住址和连续履历排除，不能为U1提供正反证。相关页面：`#/news/issue/1996-05-09/page/2`、`#/archive/record/FACTORY-STAFF-LW-1998`。

**1982报纸是1998后补印**

```text
扫描文件生成于2004
→ OCR条目在2012才人工校正
→ 查看整卷缩微胶片前后版和1982发行目录
→ 县图书馆合订本有同版同句及1982借阅章
```

闭合：可确认该句在1982公开存在；2004/2012只是数字化与OCR层。仍不能证明契文会造成滑坡。相关页面：`#/news/film/HXRB-1982-06/frame/118`、`#/news/correction/OCR-2012-884`、`#/archive/record/LIB-BOUND-HXRB-1982`。

可选误认也必须有统一返回条和摘录按钮，不能用更弱的视觉告诉玩家“这不重要”。

## 9. 分站文案与真实感合同

### 9.1 工作台

- 用词：工单、批次、参见、待核字段、来源范围、限制阅览、提交建议、受理状态；
- 禁词：任务完成、正确答案、解锁真相、收集进度、最终谜底；
- 错误提示只说明字段缺口，例如“当前材料只有时间与方向，缺少稳定身份连接键”；
- 不代玩家总结恐怖含义。

### 9.2 论坛

- 楼主和回复者有不同口癖、知识水平、错别字、引用习惯和跑题；
- 同一帖里至少有一条帮顶、一条记忆误差、一条转载、一条方法建议、一条争吵或版务处理；
- 2004原文可以出现时代性不当称呼，但现代外壳加“历史原文用语”说明；
- 不让每个网友都像档案专家；
- 关键信息不能都由同一个全知账号提供。

### 9.3 档案目录

- 句子短、机械、克制；
- 区分形成时间、收集时间、数字化时间、公开状态、受限字段；
- 不出现“毛骨悚然”“竟然”“真相是”；
- 空态讲检索格式、开放范围和档号，不讲谜题提示。

### 9.4 民俗资料网

- 是1999年高校课题/爱好站，不是邪教网站；
- 正常栏目、编校说明、参考书、失效下载和友情链接必须完整；
- 1968、1970、1982版本的差异藏在普通文本学与出处页面里；
- 不用血色、鬼脸、符咒动效强调目标句。

### 9.5 报刊扫描库

- 强调期号、版次、胶片号、OCR置信和勘误；
- 扫描件的缺口、划痕、裁边自然存在；
- 不在图片上叠作者法证旁白；
- 23:44底片必须让玩家查看整条与前后帧，不能只给裁好的人影。

### 9.6 地质资料库

- 保持工程语言：坐标、高程、岩性、封堵、剖面、累计降雨、地声；
- 不做“阴森矿洞”视觉；
- 矿道排除靠空间数据，滑坡靠自然机制；
- 超自然余味只来自与早年文本并置，不由地质页面暗示。

### 9.7 禁止的 AI 腔和作者腔

禁止大面积使用：

- “值得注意的是”“令人不寒而栗的是”“真相逐渐浮出水面”；
- “系统检测到异常”“核验成立”“线索已解锁”；
- 每段同样三句式、每人都完整表达因果、每页结尾都下结论；
- 在源站正文中写“这能证明/不能证明本案什么”的幕后口吻。

证据边界放在工作台“来源与限制”面板，不伪装成1998、2004原文。

### 10.5 来源组合

```ts
type EvidenceRule =
  | { op: "ref"; refType: "source" | "group" | "derived"; id: string }
```

### 10.6 QA 三态派生

```ts
function deriveQaStatus(requiredIds: string[]): "passed" | "pending" | "failed" {
  if (requiredIds.length === 0) throw new Error("QA_REQUIRED_IDS_EMPTY");
  const statuses = requiredIds.map((id) => {
    const status = getQaCheckStatus(id);
    if (!status) throw new Error(`QA_CHECK_UNKNOWN:${id}`);
    return status;
  });
  if (statuses.includes("failed")) return "failed";
  if (statuses.includes("pending")) return "pending";
  return "passed";
}
```

| 状态 | 原型 | 命题 | 发行 |
|---|---|---|---|
| `passed` | 正常 | 开放目标状态 | 继续检查其他门槛 |
| `pending` | 显示待复核 | 禁用，不得降格成“强支持” | 阻塞 |
| `failed` | 显示明确失败回退 | 固定为“无法判断”；若重做合同则删除旧命题，禁止保留候选式确认 | 阻塞并重做合同 |

QA 状态不进入 localStorage，玩家不能修改。

### 10.7 原型流程与证据结论必须分离

专业 QA 不能反过来让开发者无法测试后半段。派生产物增加：

```ts
type ReviewState = "validated" | "candidate_pending_review" | "rejected";

interface DerivedArtifact {
  // 其余字段见上文
  reviewState: ReviewState;
}
```

规则：

- `prototype` 下，完成规定操作即可生成 `candidate_pending_review` 产物，并继续访问后续原型页面；
- 页面必须显示世界内“该关联尚待专业复核”，终局确认状态保持禁用；
- `release` 下，控制正式命题的产物必须为 `validated`；
- `rejected` 不能推进依赖该结论的发行流程，开发者必须修改证据合同；
- 当前阶段表示“玩家做完了哪项工作”，不等于“专业结论已通过”。

因此代码阶段固定使用 `S10_U1_LINK_REVIEWED`，避免把阶段名误当QA结论；玩家可见页面不显示代码阶段名。

## 11. 状态机、存档与返回上下文

### 11.1 事件式存档

存档键：

```text
zsq:v3_2:save:main
zsq:v3_2:save:staging
zsq:v3_2:settings:v1
```

```ts
interface SaveV3 {
  schemaVersion: 3;
  worldVersion: "zsq-v3.2";
  runId: string;
  revision: number;
  startedAt: string;
  updatedAt: string;
  contentNoteAccepted: boolean;
  events: StoryEvent[];
  claimDrafts: ClaimDraft[];
  playerNotes: PlayerNote[];
}
```

不要保存几十个布尔值。`viewedIds/resultIds/grantIds/closedFalsePathIds/currentStage` 均由白名单事件归约。事件至少包括查看来源、运行工具、生成结果、闭合支路、申请/取得授权、附加命题来源、设置命题状态、发布/阅读更新、提交材料包。

规则：

- 工具结果不直接保存正文，只保存规范输入和结果 ID，重开后重新计算；
- 稳定 `eventKey` 防重复推进；
- 写 `staging`，验证成功后写 `main`，再删除 `staging`；
- 两份都有效时取 revision 较高者；
- `completed=true` 不可信，重开必须重新验证所有依赖和 QA；
- localStorage 不可用时降级内存模式并提示“本次进度仅在当前页面有效”；
- JSON 损坏时提供空白会话、清除本机损坏进度、复制诊断摘要，不白屏、不把原 JSON 插 DOM；
- 不兼容旧存档明确提示安全清空，不猜测迁移；
- 重置文案“清除本机复核进度”，二次确认，只清本游戏键。

### 11.2 返回上下文

```ts
interface ReturnContext {
  fromHash: string;
  sourceSiteId: string;
  query?: string;
  page?: number;
  scrollY: number;
  focusElementId?: string;
  openedArtifactId?: string;
}
```

- 可分享的查询词、分页、快照时间写入 Hash；
- 滚动和焦点进入 `history.state`/内存；
- 返回恢复搜索词、页码、滚动和原链接焦点；
- 没有历史来源时回当前站首页；
- 抽屉和弹窗关闭后把焦点还给触发按钮；
- 工作台返回条必须位于档案/论坛/报刊正文外；
- 真线索、噪声、错误路径都用同一返回机制。

## 12. 限制阅览与公开深链

公开论坛、目录、民俗、报刊、地质页面永远不按阶段隐藏。阶段只控制：

1. 工作台是否已生成某项比较结果；

## 15. 视觉、移动端与无障碍

### 15.1 视觉原则

- 六套系统像由不同年代和维护团队制作，不追求统一高级感；
- 工作台可现代，但外站不能共享同一种大圆角卡片、阴影、渐变按钮和英文 eyebrow；
- 目标行和普通行同权；
- 真实感来自普通用途、密度、缺页、错误态、字段歧义，而不是做旧滤镜；
- 悬疑来自数据对齐，不使用鬼脸、血手印、闪屏、突发音效。

### 15.2 响应式

必须通过 390×844、640×900、1440×900：

- 无页面级横向溢出；
- 宽表在自身容器横滚，有可见提示，关键操作列可见或卡片化；
- 字段型表格在移动端保留列名，不能变成无标签数值堆；
- 扫描件先显示材料再显示元数据，提供适宽、100%、放大与拖动；
- 固定摘录按钮不遮正文、表格末行、错误提示和提交按钮；
- 旧站侧栏在移动端不能把核心文章推到很后面；
- 弹窗和抽屉小屏改全屏或底部面板。

### 15.3 无障碍

- 语义化标题、表格、表单、按钮和导航；
- 所有输入有可见 label；错误用 `aria-invalid`、`aria-describedby`；
- 抽屉/弹窗 Escape 关闭、焦点困在内部、关闭后恢复；
- 新工作更新聚焦新内容，不越过反转直达终局表单；
- 键盘可完成拖放等价操作；
- 核心颜色对比达到 WCAG AA；
- 尊重 `prefers-reduced-motion`；
- 图片有准确 alt；扫描件有转写；音频有转写和等价文本流程；
- 关闭的抽屉内容退出 Tab 序列。

## 16. 安全与稳健性

- 玩家文本只用 `textContent`；结构化内容通过白名单渲染器；
- 禁止 `eval`、`new Function`、未净化 `innerHTML`；
- 查询索引用 `Map`，不让原型链键命中；
- URL逐段解码放进 `try/catch`；
- 玩家输入和 URL 参数均转义；
- 不打开真实第三方域名；
- 外部请求数必须为0；
- CSP建议：`default-src 'self' data: blob:; connect-src 'none'; object-src 'none'; base-uri 'none'`，同时验证 `file://` 兼容；
- 受限数据的“界面门禁”不能宣传为密码学安全；
- `dist` 扫描不得出现 author合同、creatorTruth、私有死亡原句、遗传序列、专业评审原始附件。
