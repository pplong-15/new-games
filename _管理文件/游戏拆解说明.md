# 游戏拆解说明（为什么这样拆解）

> 更新：2026-08-23
> 用途：说明我们做「游戏拆解」的**母的（目的）**、方法、以及当前状态，方便随时回顾。

---

## 一、我们为什么做游戏拆解？（母的）

**一句话：为了让 AI Agent 能修改游戏。**

我们要建设的是一个**共建网页游戏社区**——玩家可以用自己的 Agent（ChatGPT/Grok）把游戏改造成自己的版本（改线索、改关卡、改故事）。但要实现这个，先要解决一个问题：

> **游戏是打包成单个巨型 HTML 文件（10MB~32MB）的**，AI Agent 根本处理不了这么大的文件，也分不清哪些能改、哪些不能改。

所以必须先「拆解」——把巨型单文件拆成模块化结构，让 Agent 能：
1. **读懂**：文件变小、结构清晰
2. **改对**：有「可修改清单」，知道哪里能改、哪里不能碰
3. **安全**：引擎和素材只读，Agent 只能改故事文本和主题配色

**拆解不是目的，是手段。母的是让游戏「可被 AI 修改」，支撑整个共建社区。**

## 二、拆解前后对比

### 拆解前（单文件）
```
鬼媒婆.html（32MB）
└─ 所有内容混在一起：样式 + 引擎 + 故事数据 + base64图片 + 字体
```

### 拆解后（模块化）
```
ghost-matchmaker-modular/
├── index.html          入口
├── style.css           视觉主题（可改：配色/字体）
├── game-core.js        引擎（只读）
├── world-content.js    故事内容（可改：人名/对白/档案/线索）
├── app.js              界面逻辑（只读）
├── manifest.json       可修改清单（机器可读，Agent 先读这个）
├── README.md           Agent 修改说明
└── assets/             图片/字体（只读）
```

**关键**：`manifest.json` 明确标记了 `engine`（只读）和 `content`（可改）——这是 Agent 改游戏时的「安全边界」。

## 三、拆解怎么做？（方法论，已沉淀为 skill）

整套方法沉淀成了可复用 skill：`~/.agents/skills/html-game-decompose/`

核心步骤：
1. **分析结构**：统计 `<style>`/`<script>`/base64 资源数量
2. **识别角色**：判断每段 script 是引擎、内容还是界面
3. **拆解**（`decompose.py`）：
   - 抽 CSS → style.css
   - 抽 JS → game-core.js / world-content.js / app.js
   - 抽 base64 图片/音频/字体 → assets/ 文件
   - 生成 index.html + manifest.json + README.md
4. **验证**：无残留 base64、图片引用正确、JS 行数一致、本地能跑

skill 位置：
- `~/.agents/skills/html-game-decompose/SKILL.md`（方法说明）
- `~/.agents/skills/html-game-decompose/decompose.py`（通用拆解脚本）

## 四、拆解结果用在哪？

拆解后的游戏**接入了 MCP 接口**，形成完整的「改游戏」闭环：

```
Agent 经 MCP 拉取模板（manifest + 可修改内容 world-content.js/style.css）
  → Agent 用玩家自己的 token 修改内容
  → 提交修改 → 后端自动构建上架 → 成为特别版
  → 他人点星认可
```

对应的 MCP 接口：
- `GET /api/mcp/games/{id}/template` → 拉取可修改模板
- `POST /api/mcp/submit` → 提交修改
- `GET /api/mcp/submissions/{id}` → 查审核状态

## 六、为什么「先拆解，再接入 MCP」是这个顺序？

1. **先拆解**：不拆解，Agent 面对 32MB 单文件寸步难行——读不懂、改不动、易弄坏。
2. **再接入 MCP**：拆解后有了清晰的模块和清单，MCP 才能把「可修改的部分」安全地交给 Agent。
3. **安全边界**：拆解时就把引擎标记只读，Agent 永远碰不到引擎逻辑——这是整个方案的安全底线。

**一句话总结：拆解 = 给游戏做「手术前准备」，MCP = 让 AI 当「能安全操作这台手术的医生」。**
