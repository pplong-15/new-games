# 金鹊录像厅 · 试玩审查施工单（发给 grok）

## 一、这是什么

「金鹊录像厅」是一款**封闭世界仿网页调查游戏**（对标《大学生登山失踪事件》），多文件 HTML，
不是单文件。目标：达到**上线标准**，做严格试玩审查，产出结构化问题清单。

游戏核心：玩家姓方南星，表亲陆小棠发短信让他去金鹊西路一家停更的录像厅官网取留座票。
玩法主循环：**读页 → 从正文抽一个汉字词 → 顶栏搜索 → 打开隐藏页**。最后登录、终局二选一（退票/坐到完）。

## 三、试玩要求（严格，上线标准）

### 玩家轨（尽可能实际走流程）
用 shell 里的 Chrome headless（`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless`）
或 playwright 实际打开页面、截图、走流程。至少验证：
1. **开局三问**：打开 introduction.html 后，玩家能否答出「我是谁 / 现在要干嘛 / 做了有啥用」？
2. **第一词链路**：首页黄色公告 → 搜「加映场」→ 是否打开 blog-jiaoying？
3. **登录链路**：田麦空间读凭据 → 搜「场记台」→ 登录（田麦/坐到完）→ 能否进 handbook？
4. **终局链路**：5 条 fact（票根/老侯/陆小棠/空座/田麦）读齐 → 搜「末班票」→ 选择页 → 两结局都能出？
5. **卡点**：有没有走不通 / 迷路 / 死循环 / 不知道下一步搜什么？

### 代码轨（通读源码验证逻辑）
通读 gen-pages.js（604 行全部文案）+ engine.js + keywords.js + keyword-search.js，验证：
1. 24 个搜索词的「出处」——每个词是否真的在某个**玩家能先到达的页面**正文里出现过？（冷门词尤其要查，比如「寻场记」「还灯债」「来访」「关站」）
2. 门禁 gate 逻辑：未解锁跳 forbidden、handbook/log 需登录，是否无漏洞（比如能否绕过登录直接开 handbook）？
3. 终局判定：`endingNeed` 五条 fact 是否都能通过正常流程拿到？
4. 存档：localStorage 键、版本号、清除存档是否正常？

### 文案审查（去 AI 味标准）
按「口语化、像真人说话、恐怖从细节漏出来、不拿腔作调」的标准，逐页扫文案：
- 有没有 AI 腔（空泛形容词堆砌、金句感、指代模糊「那个」指啥）
- 有没有逻辑小刺（前后矛盾、时间线对不上）
- 有没有「拿腔作调」的表演腔（这是最忌讳的）

### 素材审查（图↔文一致）
15 张配图逐一对应文案，查：图的内容和文案描述是否一致、有没有文字水印/错字、风格是否统一。

## 四、产出格式（严格遵守）

一份 markdown 报告，必须包含：

1. **四维评分**：卡点 / 文案 / 线索逻辑 / 素材，每维 PASS 或列问题
2. **缺陷分级**：
   - **P0 必改**：主线卡死、核心逻辑断裂、伦理误导
   - **P1 建议改**：质量差、进度提示缺失、新手引导缺失、机制崩坏
   - **P2 打磨**：风格统一、指代收敛、细节瑕疵
3. 每条缺陷必须带**代码定位**（文件名 + 具体文字/函数），让作者能直接改
4. 明确标注：哪些是「实玩验证过的」，哪些是「仅代码推演、未实玩确认」

## 五、硬规则

- 不要改任何文件，只读 + 试玩 + 报告。
- 不要编造试玩结果——做不到实玩的部分，诚实标「未覆盖，待实玩」。
- 报告用中文。
